# 当前问题

在当前微服务架构下，用户的会话信息需要在网关层和应用层之间或者应用层的多个服务之间进行共享，且网关层与应用层的实现技术栈具有差异性，
分别有使用 Spring Cloud Gateway实现的网关服务，使用Spring MVC实现的业务API服务或者使用 Spring Cloud Function实现的运行在AWS Lambda 上的Servless服务。
所以需要提供一种能够抹除不同运行环境下的技术使用差异性，且能够保证跨服务下的数据高可用性和数据一致性的会话管理功能。

# 解决方案

将所有会话数据存储在所有服务都可以访问的集中式数据存储中，使用非关系型数据库 Valkey 作为集中式数据存储对象。
以网关层作为请求的唯一入口，在网关层使用 Spring Session 实现会话管理，为认证通过的请求创建出会话数据，并将会话数据的唯一标识符SessionID作为Cookie存放在客户端本地。
客户端携带存储在本地 Cookie 中的会话数据的唯一标识符SessionID发起请求时，网关层就可以通过SessionID校验会话的有效性，延长会话生命周期，
同时为了将Spring Session管理的会话数据存储结构与业务上下文进行解耦，方便数据结构拓展，以及避免高频读写业务数据对整个会话对象的影响，将会话数据拆分为了
会话骨架 和 会话上下文，并且为了进一步隔离框架数据与业务数据，将会话上下文按照框架领域和业务领域分割为复数条独立的会话上下文属性键进行管理，将同一会话上下文中所有会话上下文属性键都存放在一条会话上下文属性索引键，会话骨架只保留会话上下文属性索引键。
在基于框架领域和业务领域，提供对应的会话上下文属性操作方法，以限制对会话上下文属性的非法操作。

本功能旨在澄清跨服务下从网关层到应用层之间的会话管理流程，包含会话生命周期，并不包含对作为会话管理同一入口的网关层的完整功能的设计检讨和应用层如何获取上下文ID的设计检讨，也不包含以下有关安全性的功能检讨。详见 Gateway的功能设计 和 tracebility的功能设计。
如：
 对会话数据的存储进行加密
 利用 SSL/TLS 对数据传输进行加密
 利用安全 Cookie 策略，防范 XSS攻击，CSRF攻击等。
 服务与服务之间的身份验证

本功能提供的会话数据操作方法依赖HTTP请求头 Cookie中携带的会话唯一标识符 SessionID，
关于 Spring Cloud Function 在 AWS Lambda下的请求上下文如何获取到SessionID的实现方式不在本功能的检讨范围对象之中，
详见Spring Cloud Function对应功能的设计。

# [客户端｜服务端]关键点（可选，另外可以按需增加子主题）

1. 框架领域和业务领域的各自的完整上下文属性键由组件根据传入的字段名进行拼接
2. 字段名只能使用小写英文字母，半角数字，半角符号 - ，_， : 。
3. 当字段名不符合上述约束时，抛出异常或发出异常通知。
4. 推荐使用半角:作为长字段的分隔符。

本功能定义的操作组件在传入字段名正确的情况下，被调用过程中或者调用产生的异常，统一转换为 SessioinAccessException向调用方抛出或者发出通知，并保存原始异常。
